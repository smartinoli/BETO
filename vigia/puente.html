Puente Telegram

Para que el Vigía corra solo cuando tú escribes: sin horarios, sin sesiones esperando, sin nada encendido de fondo. Se configura una vez, en unos 15 minutos, y es gratis para siempre.

¿Ya lo instalaste y el bot no contesta?

Actualicé el código del puente: ahora nunca se queda callado — si algo falta, te lo dice por el chat o al abrir su dirección en el navegador. Ve al paso 2.6, pega el código nuevo (botón de copiar), aprieta Deploy, y luego abre la dirección de tu Worker: el diagnóstico del paso 4 te dirá exactamente qué falta.

Escribes /barrer→ Telegram avisa al puente→ El puente despierta al Vigía→ Te llega el resultado

0 Ten esto a mano

Antes de empezar, junta estos dos datos. Son los mismos que ya pusiste como secretos en GitHub, así que si los tienes guardados, perfecto; si no, aquí va cómo recuperarlos.

Token del bot — se ve así: 8123456789:AAE...
¿Perdido? En Telegram escríbele a @BotFather → /mybots → tu bot → API Token.
Tu chat id — un número como 5123456789
¿Perdido? En Telegram escríbele a @userinfobot y te lo dice.

Estos dos datos y el token de GitHub del paso 1 son llaves: van solo en Cloudflare. No los pegues en chats ni los guardes en el repositorio.

1 Token de GitHub ≈ 3 min

Es el permiso que necesita el puente para despertar al Vigía. Lo creas limitado a un solo repositorio, así que no puede tocar nada más.

1.1Abre github.com/settings/personal-access-tokens/new (estando con tu sesión iniciada). Es el generador de tokens Fine-grained.
1.2En Token name escribe: vigia-puente
1.3En Expiration elige el plazo. Si eliges 90 días, en 90 días el bot dejará de responder y tendrás que crear otro token y actualizarlo en Cloudflare. Si prefieres no acordarte, elige No expiration.
1.4En Repository access marca Only select repositories y en el desplegable elige BETO.
1.5Baja a Permissions → Repository permissions. Es una lista larga. Busca Contents y cambia su desplegable de No access a Read and write.
1.6Baja del todo y aprieta Generate token. Si pide confirmar, confirma.
1.7Te muestra el token una única vez: empieza con github_pat_.... Cópialo y pégalo en algún lado seguro (notas del teléfono, gestor de contraseñas). Si lo pierdes, se crea otro y listo.

¿Por qué Contents y no Actions? Porque el evento que despierta al Vigía (repository_dispatch) se autoriza con el permiso de contenidos. Con Actions solo, GitHub responde 403 y el bot no arrancaría.

2 Crear el puente en Cloudflare ≈ 5 min

Cloudflare Workers es gratis hasta 100.000 llamadas al día — tú harás unas pocas decenas. No pide tarjeta ni dominio.

2.1Entra a dash.cloudflare.com/sign-up y crea la cuenta con tu correo. Verifica el correo que te llega.
2.2Ya dentro, en el menú de la izquierda busca Compute (Workers) o Workers & Pages y entra.
2.3Aprieta Create application (o directamente Create Worker) → elige Hello World / Start with Hello World!
2.4En el nombre escribe vigia (en minúsculas) y aprieta Deploy. Espera a que diga que quedó desplegado.
2.5Verás la dirección de tu puente, del tipo https://vigia.tucuenta.workers.dev. Anótala: la necesitas en el paso 5.
2.6Aprieta Edit code (o </> Edit code, arriba a la derecha). Se abre un editor con código de ejemplo.
2.7Borra todo lo que hay en el editor (Ctrl/Cmd+A y luego Suprimir) y pega el código de abajo en su lugar.
2.8Aprieta Deploy (arriba a la derecha) y confirma. Va a quedar funcionando aunque todavía le falten las variables del paso 3.

3 Las cinco variables ≈ 4 min

El código que pegaste no tiene tus llaves escritas dentro (así es más seguro): las lee de estas variables.

3.1En tu Worker, ve a la pestaña Settings → Variables and Secrets (en algunas versiones: Settings → Variables).
3.2Aprieta + Add y crea una por una las cinco de la tabla. Para las tres marcadas como Secret, elige el tipo Secret (queda oculta); para las otras dos, Text sirve igual.
3.3Cuando estén las cinco, aprieta Deploy otra vez para que el puente las tome.
Nombre exactoTipoQué va adentro
TG_TOKENSecret El token de tu bot, completo con los dos puntos: 8123456789:AAE...
GH_TOKENSecret El token de GitHub del paso 1 (github_pat_...)
TG_SECRETSecret Una palabra larga que inventes tú, sin espacios ni tildes. Ej: beto-puente-2026-x7k9. Sirve para que nadie más pueda fingir ser Telegram. Anótala: la necesitas en el paso 5.
TG_CHATText Tu chat id, solo el número: 5123456789
GH_REPOText Exactamente: smartinoli/BETO

Los nombres deben ir idénticos, en mayúsculas y con guión bajo. Si uno queda mal escrito, el puente no lo encuentra y responde con error.

4 Probar el puente solo ≈ 1 min

Antes de conectar Telegram, comprueba el puente: abre en el navegador la dirección de tu Worker (la del paso 2.5). Te responde con un diagnóstico:

{
  "puente": "activo · versión 2",
  "TG_TOKEN": "ok",
  "GH_TOKEN": "ok",
  "TG_SECRET": "ok",
  "TG_CHAT": "ok (termina en …789)",
  "GH_REPO": "smartinoli/BETO",
  "resumen": "✓ Todo configurado. Escríbele al bot para probar."
}
BienSi el resumen dice ✓ Todo configurado, sigue al paso 5.
FaltanSi dice ⚠ Faltan variables: …, vuelve al paso 3 y agrega las que nombra. Recuerda apretar Deploy después.
MalSi dice Hello World!, el código no se pegó: vuelve al 2.6, borra TODO el editor y pega de nuevo. Si sale error 1101, el código quedó cortado a la mitad: pégalo completo.

5 Conectar Telegram ≈ 2 min

Aquí le dices a Telegram a qué dirección avisar. Llena los tres campos y la página te arma la dirección exacta — así no hay riesgo de equivocarse escribiéndola.

Estos datos no salen de tu navegador: la página los usa solo para construir el texto, no los envía a ninguna parte.

5.1Copia la dirección que aparece y ábrela en una pestaña del navegador.
5.2Si responde {"ok":true,"result":true,...}, quedó conectado.
5.3Si responde "ok":false, lee el mensaje: casi siempre es el token mal copiado o la dirección del Worker con un espacio de más.

6 La prueba de fuego ≈ 1 min

6.1En Telegram, mándale /estado a tu bot.
6.2Debe contestarte ⏳ Recibido: /estado — trabajando… en el acto. Eso significa que el puente funciona.
6.3En menos de un minuto llega el mensaje del Vigía con la cuota de API y el último barrido. Eso significa que GitHub también respondió.
6.4Si todo salió bien, prueba /barrer: el barrido completo tarda unos 2 minutos.

Desde aquí en adelante: el sistema no corre nunca solo. Duerme hasta que tú escribes, a cualquier hora del día.

Si algo no funciona

No contesta nada, ni el "⏳ Recibido"

El aviso de Telegram no está llegando al puente. Abre esta dirección (reemplaza tu token):
https://api.telegram.org/botTU_TOKEN/getWebhookInfo

  • "url":"" vacío → el paso 5 no se aplicó: repítelo.
  • "last_error_message" con algo → ahí está la causa. Si dice Wrong response from the webhook: 401, la palabra secreta del Worker (TG_SECRET) no coincide con la que pusiste en la dirección del paso 5.
  • Todo bien pero igual nada → revisa que TG_CHAT sea exactamente tu chat id: si no calza, el puente ignora los mensajes a propósito.
Dice "⏳ Recibido" pero nunca llega el resultado

El puente funciona y GitHub aceptó el aviso, pero el Vigía falló. Entra al repositorio → pestaña Actions → workflow Vigía, y mira la última ejecución:

  • No aparece ninguna ejecución nueva → el token de GitHub no tiene el permiso Contents: Read and write (paso 1.5), o expiró.
  • Aparece en rojo → ábrela y lee el error del paso "Atender el comando". Mándame ese texto y lo resolvemos.
Responde "❌ No pude despertar al Vigía (GitHub respondió 404)"

Casi siempre es GH_REPO mal escrito (debe ser smartinoli/BETO, respetando mayúsculas) o el token creado sin acceso a ese repositorio (paso 1.4). Un 401 o 403 en cambio es token vencido o sin el permiso de Contents.

Quiero desconectarlo o cambiar de puente

Para desconectar Telegram del puente:
https://api.telegram.org/botTU_TOKEN/deleteWebhook
Después de eso el bot deja de responder hasta que vuelvas a hacer el paso 5.
